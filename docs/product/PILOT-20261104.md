## Findings so far (day 0, in order of value)

1. **Installation bug, fixed in place:** the key path was prefixed to the hook command as `VAR=… A=…; exec` — a plain
   assignment, not exported — so the first bundles came out `authenticity=unsigned`. Fix: `export VAR=…;`. The
   snippet printer should emit the export itself (follow-up).
2. **Root dotfiles are unreadable through `Read` in an enabled project.** `.gitleaks.toml`, `.gitignore`,
   `.editorconfig` fall into `invalid_referenced_contract` (the v1 intent path must start with `[A-Za-z0-9]`). Same
   class as the 2026-10-20 pilot's finding 1, now hitting benign files. **Resolved by ADR 0036** (path rule 1.1 +
   `sensitive_path_policy_v2`): benign dotfiles delivered, `.env` denied by the PDP with a bundle.
3. **The 1b grammar denies the agent's own working style.** Four of the agent's first five Bash commands in this
   repository were `uncovered_bash_ambiguous`: `|` inside double quotes is split before `shlex` (a trailing `\`
   then fails), `python3 -c` containing `open(` is opaque, `$`/`<` next to `sed`/`head`/`wc` is an expansion.
   Each is the parser's stated ceiling; together they are the measurable cost of 1b. Candidates: quote-aware
   segment splitting; `open(` only when a path-like literal follows.
4. **`bash script.sh` passes.** The agent wrote its smoke test to a file and ran it; the gate sees only the top-level
   command. Documented ceiling (ADR 0028), observed on day 0.
5. **Re-pin discipline.** Every commit in this repository that touches `integration/`, `tools/`, `runtime/` or the
   hooks makes `adf doctor` report `control_plane_tampered` for *all* enabled projects until `adf doctor --pin`.
   Intended; the cost is now measured per commit.
6. **A tamper deny locks the agent out blind.** After the pilot PR merged, every gated call in this repository
   was `control_plane_tampered` — including `adf doctor` through `Bash`, so the agent could neither diagnose nor
   re-pin. That is the intended property (the agent must not self-heal pins), but the deny message names no
   label; the human had to run `adf doctor` in a terminal. Cause: the manifest was pinned on the feature branch
   and `main` after the squash merge differed in two files. Follow-up: append the divergent labels (never
   paths) to the deny reason.
7. **`adf doctor` outside the hook reports a spurious divergence.** Run from a terminal without
   `ADF_EVIDENCE_KEY_FILE`, the snapshot lacks `host:ADF_EVIDENCE_KEY_FILE` and the doctor prints it as
   tampered while the hook (which exports the variable in its command) sees it intact. Follow-up: the doctor
   should take host env files from the registered hook command, or print "not set in this shell" instead of ✗.
9. **The manifest is per checkout, and the agent switches branches.** Two lockouts in one day had the same root:
   `adf doctor --pin` ran on a feature branch (the ship script had left the clone there) and the next `checkout main`
   changed two pinned files. While the agent develops the control plane on a branch, every gated call in this repo
   is denied until merge + re-pin. Decision: this repository leaves the pilot (`adf projects disable`); the other
   three stay. Follow-ups: `adf doctor` prints branch/commit next to the verdict; a manifest mode accepting any
   hash reachable from `origin/main` would loosen ADR 0027 and needs its own ADR.
8. **The 1b grammar, second class:** `grep -e PAT1 -e PAT2 FILE` — only the first operand is treated as a
   pattern, so a `*` in the second is a glob in a "path" → `uncovered_bash_ambiguous`. Same bucket as finding 3.
