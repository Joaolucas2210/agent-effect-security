# Quickstart: an isolated read decision

**English** · [Português (Brasil)](QUICKSTART.pt-BR.md)

This demo calls ADF's real `PreToolUse` entry point with synthetic payloads. It does not register a client hook, touch your agent settings, or claim that a real Claude Code session was tested. Requirements: Git, Make, Python 3.10+ with `venv`, and a local clone. `make install-dev` installs the editable package into the activated venv; ADF is not published to PyPI. Use a disposable shell and directory.

## 1. Install and prepare a synthetic project

From the ADF clone:

```bash
python3 -m venv .venv
source .venv/bin/activate
make install-dev
adf version                         # must match VERSION in this clone

DEMO_ROOT="$(mktemp -d)"
mkdir -p "$DEMO_ROOT/project" "$DEMO_ROOT/home"
export ADF_HOME="$DEMO_ROOT/home/.adf"
export ADF_EVIDENCE_KEY_FILE="$ADF_HOME/evidence.key"
printf 'public demo\n' > "$DEMO_ROOT/project/README.md"
printf 'synthetic only\n' > "$DEMO_ROOT/project/.env"
git -C "$DEMO_ROOT/project" init -q
git -C "$DEMO_ROOT/project" add README.md .env
git -C "$DEMO_ROOT/project" -c user.name=Demo -c user.email=demo@example.invalid commit -qm fixture
adf key init "$ADF_EVIDENCE_KEY_FILE"
adf projects enable "$DEMO_ROOT/project"
```

The fixture has no real credential. Its allowlist is generated by this reference demo for each requested path; it is **not** a reviewed host-owned policy. For a real project, build and pin an exact allowlist with [`adf policy build`](../../ai-development-framework/policy-packs/effect-security-read-v0/README.md) and set `ADF_READ_POLICY_FILE` and `ADF_READ_POLICY_SHA256` for the session.

## 2. Ask the installed edge for two decisions

```bash
printf '{"hook_event_name":"PreToolUse","tool_name":"Read","session_id":"demo","tool_input":{"file_path":"%s"}}' "$DEMO_ROOT/project/README.md" | CLAUDE_PROJECT_DIR="$DEMO_ROOT/project" adf hook
printf '{"hook_event_name":"PreToolUse","tool_name":"Read","session_id":"demo","tool_input":{"file_path":"%s"}}' "$DEMO_ROOT/project/.env" | CLAUDE_PROJECT_DIR="$DEMO_ROOT/project" adf hook
```

Expect an `allow` with `delivered/read_delivered` for `README.md` and a `deny/invalid_scope` for `.env`. Both reach the adapter and produce bundles in this fixture. The request goes through the real hook, PDP, PEP and snapshot read, but no native client read occurs here. The resulting mode is `gate_only`: ADF's decision and snapshot check do not prove bytes a native tool would deliver. Contract and deny-only gate failures can instead leave only a journal entry.

## 3. Verify and clean up

```bash
find "$ADF_HOME/evidence" -name '*.json' -not -path '*/_attempts/*' -print
adf verify "$(find "$ADF_HOME/evidence" -name '*.json' -not -path '*/_attempts/*' -print -quit)" --key "$ADF_EVIDENCE_KEY_FILE"
adf projects reasons
```

Expect `verified ... authenticity=valid ... delivery_mode=gate_only`. `--key` verifies an HMAC using the same secret that issued the record; it is not independent public verification. Without `--key`, `authenticity=not_checked`. Keep the key on the host; do not give it to an outside auditor. The demo directory may be removed after inspection. See [what evidence proves](BOUNDARY.md#evidence-is-the-record-telemetry-only-visualizes).

## Opt in a real client later

`adf hook-snippet claude` or `adf hook-snippet codex` **prints JSON; it does not install anything**. Review and merge the emitted `hooks.PreToolUse` entries into the client's settings without replacing existing hooks. Restart the client so it loads the new registration. Then run `adf projects enable /absolute/path/to/repository` and `adf doctor --pin` from the host **after** the registration is in place. The hook command exports the evidence-key path only if a key existed when the snippet was printed; regenerate and review the snippet after key creation. A real allowlist is session-bound and must be pinned separately. See the [host install and trial guide](../../ai-development-framework/docs/trials.md#many-projects-one-hook-req-mp-01) and the [support matrix](BOUNDARY.md#support-matrix) before enabling a working repository.

To disable a project, run `adf projects disable /absolute/path/to/repository`. To remove the integration, remove only ADF's hook entries, preserve other hooks, restart the client and have the host review the pin. If ADF's executable is missing or fails before a decision, the supplied wrapper exits without a decision; the client may proceed under its own permissions. This is not a global fail-closed boundary.
