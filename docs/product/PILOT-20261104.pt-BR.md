## Achados até agora (dia 0, em ordem de valor)

1. **Bug de instalação, corrigido no lugar:** o path da chave foi prefixado ao comando do hook como `VAR=… A=…; exec` —
   atribuição simples, não exportada — e os primeiros bundles saíram `authenticity=unsigned`. Correção: `export VAR=…;`.
   **Entregue:** `adf hook-snippet` agora emite o export quando o host tem chave.
2. **Dotfiles na raiz não são legíveis via `Read` em projeto habilitado.** `.gitleaks.toml`, `.gitignore`,
   `.editorconfig` caem em `invalid_referenced_contract` (o path do intent v1 precisa começar com `[A-Za-z0-9]`). Mesma
   classe do achado 1 do piloto de 2026-10-20, agora atingindo arquivos benignos. **Resolvido pela ADR 0036** (regra
   de path 1.1 + `sensitive_path_policy_v2`): dotfiles benignos entregues, `.env` negado pelo PDP com bundle.
3. **A gramática 1b nega o jeito de trabalhar do próprio agente.** Quatro dos cinco primeiros comandos Bash do agente
   neste repositório foram `uncovered_bash_ambiguous`: `|` dentro de aspas duplas é quebrado antes do `shlex` (um `\`
   solto falha depois), `python3 -c` contendo `open(` é opaco, `$`/`<` ao lado de `sed`/`head`/`wc` é expansão. Cada um é
   teto declarado do parser; juntos são o custo mensurável do 1b. **Entregue (segunda passada):** quebra de segmentos
   ciente de aspas e tabelas de opções com argumento; `python3 -c` com `open(` continua opaco por escolha.
4. **`bash script.sh` passa.** O agente escreveu o smoke test num arquivo e executou; o gate só vê o comando de topo.
   Teto documentado (ADR 0028), observado no dia 0.
5. **Disciplina de re-pin.** Todo commit neste repositório que toca `integration/`, `tools/`, `runtime/` ou os hooks faz
   `adf doctor` reportar `control_plane_tampered` para *todos* os projetos habilitados até `adf doctor --pin`.
   Intencional; o custo agora é medido por commit.
6. **Um deny de tamper tranca o agente às cegas.** Depois do merge do PR do piloto, toda chamada gated neste
   repositório foi `control_plane_tampered` — inclusive `adf doctor` via `Bash`, então o agente não conseguia nem
   diagnosticar nem re-pinar. É a propriedade desejada (o agente não deve se auto-curar), mas a mensagem do deny
   não nomeia o label; o humano teve que rodar `adf doctor` num terminal. Causa: o manifesto foi pinado na branch
   e o `main` após o squash merge diferia em dois arquivos. **Entregue:** a razão do deny agora é
   `control_plane_tampered: <labels> (human: adf doctor)`; o journal mantém o código estável.
7. **`adf doctor` fora do hook acusa divergência espúria.** Rodado num terminal sem `ADF_EVIDENCE_KEY_FILE`, o
   snapshot não tem `host:ADF_EVIDENCE_KEY_FILE` e o doctor imprime como adulterado, enquanto o hook (que exporta a
   variável no comando) vê íntegro. **Entregue:** o snapshot tira os arquivos de env do host do comando de hook
   registrado quando o shell não os tem (o valor do shell prevalece).
9. **O manifesto é por checkout, e o agente troca de branch.** Dois lockouts no mesmo dia tiveram a mesma raiz:
   `adf doctor --pin` rodou numa branch de feature (o script de ship deixou o clone nela) e o `checkout main` seguinte
   mudou dois arquivos pinados. Enquanto o agente desenvolve o control plane numa branch, toda chamada gated neste repo
   é negada até merge + re-pin. Decisão: este repositório sai do piloto (`adf projects disable`); os outros três
   ficam. **Entregue:** `adf doctor` imprime `clone: <branch> @ <sha>` primeiro. Ainda aberto: um modo de manifesto
   que aceite qualquer hash alcançável a partir de `origin/main` afrouxaria a ADR 0027 e precisa de ADR própria.
8. **Gramática 1b, segunda classe:** `grep -e PAD1 -e PAD2 ARQ` — só o primeiro operando é tratado como pattern,
   então um `*` no segundo vira glob num "path" → `uncovered_bash_ambiguous`. **Entregue (segunda passada):** argumentos
   de `-e`/`--regexp`/`-f` são patterns ou arquivos de pattern, nunca paths por posição.
