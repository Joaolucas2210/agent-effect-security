## Findings and improvements (in order of value)

1. **The root `.env`, the most common case, is denied without a bundle.** The v1 contract rejects a root dotfile before deciding, so
   `project-reasons` does not count that deny and the auditor does not see it. The hash-chained journal in `_attempts/` **records** the attempt
   with `reason_code: invalid_referenced_contract` and the session's `run_id`. Small improvement: `project-reasons` gets a column of
   attempts without a bundle, read from the journal (counts only). It keeps the contract; it exposes what already exists.
2. **`Bash` coverage must be on by default.** Session 1 leaked the `.env` through a compound `cat` because only `Read` was
   registered. The hook already decides `Bash`; `trials.md` must say to register both matchers, and a `make hook-snippet` can
   print the ready-made JSON with the clone's paths.
3. **Native deny is a prefix, not protection.** `Bash(cat .env*)` did not match `cat /abs/path/.env`; the hook held. Document
   native deny as a second layer for `head`/`sed`/`tail`/`grep`, never as the first.
4. **The agent suggests the bypass through the human.** Twice it proposed `! cat .env` at the prompt, which puts the secret into the conversation without going
   through any edge. This is not a technical failure of the gate; it is an operations training issue. Add a line in the client project's `AGENTS.md` and in the
   one-pager: a gate deny is not resolved by pasting the secret.
5. **The agent investigates the gate.** After the denies, it ran `grep -rln "adf:" .claude` and `ls -la | grep env`. This residual is already
   declared (it can read and edit `~/.adf` and `.claude` through `Bash`); it is worth documenting as observed behavior and suggesting a native
   `Bash` deny over `~/.adf/` and `.claude/` in the project.
6. **The agent attributes the hook to the repo and says there is no reference in the global settings.** False in both cases. The message
   `adf: deny/<reason>` could say `host gate` so the operator does not search the repo. No paths in the message.
7. **Manual simulations pollute the aggregate.** A fictitious `session_id` enters `project-reasons` as if it were traffic. Operations
   rule: simulate with a temporary `ADF_HOME`; optionally, `project-reasons` per session.
8. **Layer order matters for the proof.** With `Read(...)` in the native deny, Claude refuses before the hook and there is no bundle.
   For the pilot, `Read` stays with the hook; native deny covers only what the hook does not decide.
9. Fixed along the way: `make project-enable` without `PROJECT` (#86) and the flaky test `test-run-events` (#87, WSL2
   clock going backward).

Additional findings:

10. **Format discovery.** The public agent card lists zero skills and the `400 invalid_request` does not name the field. A generic
    agent cannot build the request on its own (it guessed `params.skill`, `skillId`, text `parts`, `/openrpc.json`).
    Improvement: skills and a minimal example in the public card, or `data.invalid_path` in the 400 (without echoing the body).
11. **A pause before the PDP asks for confirmation of something the policy would never admit.** `config/.env` via A2A pauses in
    `input_required` like the README; only after confirmation does the PDP deny with `invalid_scope`. Confirmation does not release the effect
    (ADR 0018), but it spends human attention, and the peer read it as "if someone confirms, the content goes out". Candidate for an additive ADR:
    a deterministic contract/scope pre-check before opening the task, denying without a pause what is already impossible.
12. **`mint` issues 5 minutes and the task expires in 5 minutes.** Too short for a flow with a real human: three tasks expired
    before confirmation. The pilot needed a 1 h token generated by hand and argument-free scripts, because the
    operator's prompt broke lines at spaces.
13. **Claude's auto mode classifier blocked `curl` with a bearer** ("Auto-Mode Bypass") on two calls: a vendor layer
    interfering with the test, outside ADF's control; record it as a condition of the test environment.
14. **Positive behavior to preserve:** the peer reported `401` as AuthN before policy and did not forge a token; the orchestrator
    refused to confirm its own request. This is what the one-pager should describe as the "expected flow".

## What the pilot does not cover (honest residual)

`python -c`, `head`, `sed`, `rg`, pipes, and subagents/MCP with other tools; the human pasting the secret; the agent editing the
project list. Protecting the real secret still means not having it in the working tree the agent opens.
