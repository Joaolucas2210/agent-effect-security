# P0-C: cobertura de leitura e identidade dos bytes (2026-09-29)

> **English summary.** This matrix (2026-09-29) records P0-C read coverage for tested surfaces, not total agent coverage, using the diagnostic statuses `mediated`, `gate_only`, `uncovered` and `unsupported`. Only the MCP Python SDK 2.2.0 client (in memory and over stdio in a subprocess) calling `read_snapshot(path)` is `mediated` in tests, with delivered bytes matching the receipt hash; the Claude Code `Read` and Codex literal `cat` hooks are `gate_only` because the native tool delivers the bytes, and alternative read routes are `uncovered`. MCP inside a real Claude Code or Codex product and non-UTF-8 content are `unsupported`, and there is no issuer authentication by hash, isolation from same-UID processes or guarantee that an agent avoids other read tools; the decision is ADR 0012, which is Proposed. The full record below is in Portuguese.

Esta matriz descreve **superfícies testadas**, não cobertura total do agente.
`mediated` exige que o resultado entregue ao cliente do teste venha do mesmo
`LocalReadAdapter.read` cujo receipt registra o hash dos bytes. `gate_only`
significa autorização prévia sem controle dos bytes da tool nativa. `uncovered`
não passou por esse adapter. `unsupported` fica sem claim de cobertura.
Status é diagnóstico, fora dos enums de PDP, PEP e evidence bundle v1.

| Agente/versão ou cliente | Tool/caminho | Status | Evidência e limite |
| --- | --- | --- | --- |
| Cliente do SDK MCP Python **2.2.0**, local em memória | `read_snapshot(path)` | `mediated` no teste | Resultado `TextContent.text` igual ao snapshot; SHA-256 e tamanho iguais ao receipt do mesmo bundle. Edição não commitada no checkout não muda o conteúdo recebido. |
| Cliente do SDK MCP Python **2.2.0**, stdio em subprocesso | `read_snapshot(path)` | `mediated` no teste | Handshake, descoberta da tool e entrega testados pelo transporte real; mesmo hash do receipt. Não prova consumo pelo modelo após o cliente. |
| Claude Code, versão instalada não aferida; hook `PreToolUse` | `Read` | `gate_only` | Gate chama adapter antes da tool nativa. O cliente pode receber bytes do checkout diferentes do snapshot; offset/limit/pages não são reproduzidos no bundle. |
| Codex, versão instalada não aferida; hook `PreToolUse` | `Bash` com um `cat` literal permitido | `gate_only` | Gate aprova uma leitura, mas o Bash nativo faz a entrega. Não há binding do stdout ao receipt. |
| Claude Code ou Codex sem configuração MCP testada aqui | MCP `read_snapshot` no próprio produto | `unsupported` na matriz de produto | O SDK provou o caminho local; instalação, trust review e entrega em um cliente real não foram testados. Não transformar suporte de protocolo documentado em resultado medido. |
| Claude Code `Bash` e outras tools de leitura; Codex comandos fora do parser `cat` e outras tools | leitura alternativa | `uncovered` | Hooks atuais não mediam essas rotas. Não há garantia antibypass. |
| Servidor MCP local | conteúdo binário ou não UTF-8 | `unsupported` | Runtime v1 só entrega UTF-8; erro fechado, sem conteúdo. |

O experimento MCP é **opt-in** e não instala hooks nem MCP nos clientes.
Usa `mcp[cli]==2.2.0` como dependência opcional de `adf-control-plane`,
fixada também nos testes. A [especificação MCP 2026-07-28](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports)
define stdio; o [SDK oficial](https://py.sdk.modelcontextprotocol.io/get-started/)
fornece o transporte e valida os parâmetros. Nenhum parser JSON-RPC foi criado.
As [docs de hooks do Claude Code](https://code.claude.com/docs/en/hooks) e
[Codex](https://learn.chatgpt.com/docs/hooks) fundamentam o limite dos gates:
hooks de pré-tool podem controlar a chamada, mas não são prova dos bytes que
uma tool nativa devolve. No Claude Code, `PostToolUse.updatedToolOutput` pode
alterar o que o modelo vê, porém a tool já executou e telemetria recebeu o
resultado original; não foi adotado como contenção de leitura.

## Rodar o experimento local

O host instala `mcp[cli]==2.2.0` (ou o extra `adf-control-plane[mcp]`),
aprova previamente o JSON de policy descrito em [P0-B](../CONTROL_PLANE.md#policy-do-host-p0-b-opt-in-na-branch)
e define `ADF_TRUSTED_REPOSITORY`, `ADF_TRUSTED_REVISION` (preferir SHA de commit),
`ADF_EVIDENCE_DIR`, `ADF_MAX_OUTPUT_BYTES`, `ADF_RUN_ID`, `ADF_READ_POLICY_FILE` e
`ADF_READ_POLICY_SHA256` no processo MCP. O run ID do context da policy deve ser
exatamente `ADF_RUN_ID`. Arquivo e pin permanecem fixos no run. Em um diretório
raiz do repositório com dependências instaladas:

```bash
mcp run ai-development-framework/integration/mcp_read_server.py:mcp --transport stdio
```

O cliente chama apenas `read_snapshot` com `{ "path": "caminho/relativo.txt" }`.
O argumento não controla repositório, revisão, policy, orçamento, run ID nem
local da evidência. Resultado é apenas o texto UTF-8 do snapshot. Denial é erro
MCP com reason code estável; não devolve path, conteúdo ou exceção crua.
O servidor é inventariado em [mcp/servers.json](../../mcp/servers.json), mas
o inventário **não** instala, autentica ou aplica o allowlist: PDP/PEP fazem
o enforcement. O comando precisa ser registrado e revisado no host.

O SDK já suporta conexão stdio por clientes; integração em cliente real,
política de trust do cliente, coleta de confirmação de consumo e outras tools
precisam de um trial separado. Quem controla o ambiente do servidor controla
seus parâmetros de host. O server não abre transporte HTTP nem socket; o
cliente pode transmitir o resultado a um modelo remoto. Não há autenticação
do emissor por hash, isolamento de outros processos com mesmo UID ou garantia
de que um agente não use outras tools de leitura.

Veja [ADR 0012 (Proposed)](../architecture-decision-records/0012-mediated-stdio-read.md).
